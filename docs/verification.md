# Verification and Cal AI coverage

Verified locally September 28–29, 2026. Scope: nutrition, tracking, and chat. Subscription, paywall, and referral flows are excluded at the user's request.

## Environment and automated checks

- Expo `58.0.0-preview.8` (`next` at verification), React Native `0.88.0-rc.2`, React `19.3.0`.
- Bun 1.2.22, Node 22.23.1, Xcode 27.1.
- Dedicated iPhone 18 Pro Max simulator, iOS 27.2, plus Chromium at a narrow viewport.
- `bun install --frozen-lockfile`: passed.
- `bun run check`: TypeScript and ESLint passed; 29 tests passed (87 assertions).
- `bun run theme:check`: generated palette matches CSS.
- `bunx expo-doctor`: 20/20 checks passed.
- `bunx expo export --platform all`: iOS, Android, web, and five API routes exported.
- Native iOS development build: succeeded, zero errors and two build warnings; installed and exercised in the simulator.
- React Doctor was used as an additional source audit, not a passing release gate. Remaining diagnostics include compiler bailouts around asynchronous voice/permission code, Reanimated shared-value mutations, component complexity, and heuristic cleanup warnings. The audio hooks and animation loop have explicit teardown. Not every component is compiler-optimized.

Tests cover nutrient scaling (including grams, ounces, fractional USDA portions and sodium), calendar boundaries, history windows, rollover budgets, duplicate food/tool reconciliation, atomic tracking confirmation, persisted journal edits, bounded image/history payloads, request validation, and adult goal estimates.

## API and privacy checks

All five API routes require a valid Supabase bearer token. Live smoke tests returned 401 without auth, 400 for malformed requests, 200 for USDA search, 200 for barcode lookup, and a streamed chat response containing both text and a food tool result. A single chat sample completed in about 8.1 seconds; this is an observation, not a latency benchmark.

Attachments accept bounded inline JPEG/PNG/WebP data only. Remote image URLs are rejected. Conversation requests retain at most 60 messages and 8 MB of images; stored history retains at most 200 messages. Recent food history is limited to 14 days. A byte scan of 47 exported client files found none of the six configured private provider/service credentials. Provider and service-role credentials are server-only. Apple Health measurements are not automatically added to AI context.

## Important differences and remaining release checks

- The goal calculator is a starting estimate, not a deadline or weight-loss prediction model. It uses the [Mifflin–St Jeor equation](https://pubmed.ncbi.nlm.nih.gov/2305711/) and activity factors within the range described by [NIDDK](https://www.niddk.nih.gov/bwp). It scales the user's existing macro proportions. Its 1,500-calorie/resting-energy lower boundary is a conservative product constraint, not a universal medical threshold. Age/sex calculation inputs are not uploaded or persisted.
- Cal AI's proprietary health score, deadline-based weight projections, widgets, Live Activities, localization, and cloud account sync are not implemented. Mora avoids inventing a health score from incomplete food data.
- Android bundles compile, but no Android emulator/device walkthrough or Health Connect implementation was completed. iPad/tablet layout and production release builds need validation.
- Physical camera/barcode, microphone/headphones, populated HealthKit data, notification delivery, permission-denial recovery, offline/slow-network retry, and a full accessibility pass remain release checks.
- No backend deployment, database migration, EAS update, store submission, or production performance benchmark was performed. The configured hosted API URL was retained, not validated as a deployed version of these routes.
- This is beta software. A Metro incremental-graph error occurred during a multi-file hot reload and cleared after restarting Metro with `--clear`. Native compilation required the scoped HealthKit Swift search-path config plugin. Existing third-party development warnings include React Native Web animation fallbacks and SDK preview import notices.

## Repeatable manual regression

1. Start a development build, complete onboarding, and send “I ate a banana.” Confirm the draft and verify the same quantity/calories in Today.
2. Edit its portion to 0.5, save it as a favorite, log it again, and delete the duplicate. Reload and compare totals.
3. Search a database food and enter a known barcode. Try an unknown code and manual entry. Build a two-food meal, save it, and log a fractional serving.
4. Ask to log 500 ml of water. Confirm once, reload, and verify it cannot save twice. Exercise the same flow for steps, weight, and exercise.
5. Log a historical date and ensure its timestamp stays on that date. Check 30/90/365-day trends, latest weight and streak.
6. Estimate targets, review them, change a result manually, and save. Switch units and themes and verify persistence.
7. Attach a meal photo and a nutrition-label photo; correct the result before confirming. Exercise camera/library denial and cancellation.
8. Connect voice, speak, interrupt, mute, leave chat, and background the app. Verify microphone and audio stop appropriately.
9. Grant and deny Health/reminder permissions, import populated Health data, verify scheduled delivery, and export the journal.
10. Test a slow/disconnected network, retry, sign-out/return, large text, VoiceOver, Android, and a physical iPhone before release.

Local logs and screenshots are in `.context/` and are intentionally untracked.
